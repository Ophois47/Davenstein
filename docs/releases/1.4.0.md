# Davenstein 1.4.0

Davenstein 1.4.0 is a feature and corrective release focused on authentic Wolfenstein 3-D audio and interface behavior, expanded classic control and rendering options, verified retro-controller compatibility, safer display-mode handling, and gameplay correctness

The release adds selectable PC Speaker audio, optional mouse push-to-move controls modeled after Wolfenstein 3-D, a Classic 320-wide rendering mode, permanent support for the tested Retrolink SNES controller on macOS, and the original randomized Wolfenstein 3-D quit-confirmation experience

Davenstein 1.4.0 retains the existing Windows, Linux, macOS, FreeBSD, Android, private iPhone and iPad, and alternate-architecture support model

## Major Additions And Corrections

* Added authentic PC Speaker sound playback using the original beeper-tone assets
* Added a persistent SFX Device option for switching between AdLib and PC Speaker audio
* Added verified macOS support for the Retrolink SNES controller identified as USB device `0079:0011`
* Added optional classic mouse push-to-move behavior modeled after Wolfenstein 3-D
* Reworked the expanded Control Options menu into a fixed-spacing scrolling viewport
* Increased the player run-speed multiplier from `1.6` to `1.75`
* Added a Classic 320-wide render scale and additional low-resolution choices
* Prevented color and depth render targets from becoming mismatched during canvas resizing
* Filtered exclusive-fullscreen choices to display modes that the active monitor can actually set
* Replaced exclusive fullscreen with borderless fullscreen on macOS
* Prevented fast projectiles from tunneling through walls or striking the player through intervening geometry
* Restored Wolfenstein 3-D open-door closing behavior
* Corrected an intermittent dropped first shot caused by system ordering
* Corrected the Get Psyched backdrop, HUD transition, progress-bar placement, and status-bar edge treatment
* Restored the nine original randomized Wolfenstein 3-D quit taunts
* Prevented quit-confirmation dismissal input from also closing the in-game pause menu

## Authentic PC Speaker Audio

Davenstein now provides an authentic PC Speaker sound mode using the original beeper-tone assets stored under `sounds/sfx/pc`

The PC Speaker library loads sounds through their canonical Wolfenstein 3-D sound-number mapping. Gameplay sound events are translated to the corresponding PC Speaker entry when one exists, while an unmapped event safely retains its digitized-sample playback path

PC Speaker playback follows the same managed-sound replacement rules used by the digitized path, so newly triggered pickup and other category-managed sounds replace the previous sound instead of creating uncontrolled overlap

## Persistent SFX Device Selection

The Sound Options menu now includes an SFX Device row that switches between AdLib and PC Speaker playback

The row accepts left, right, and confirmation input through the existing keyboard, mouse, gamepad, and touch-capable menu systems

The selected sound device is represented through a stable settings string and participates in the normal capture, serialization, loading, and application paths. The selection therefore survives quitting and restarting Davenstein

## Retrolink SNES Controller Support

Davenstein now installs the physically verified macOS SDL mapping for the Retrolink SNES controller identified by USB vendor and product ID `0079:0011` before Bevy initializes its gamepad backend

The controller's repaired vertical and horizontal axes are translated into continuous forward movement, backward movement, left turning, and right turning during gameplay. Hysteresis-controlled input edges provide stable menu navigation without repeatedly moving the cursor from a held direction

The physical A and B controls now produce the intended gameplay and menu confirmation behavior, and the digital yaw contribution is reduced to make directional taps more precise

The mapping is restricted to the matching controller and macOS platform. Explicit user-provided mappings remain authoritative, and modern analog gamepads continue using their existing input paths

## Classic Mouse Push-To-Move

Control Options now includes optional classic mouse push-to-move behavior modeled after Wolfenstein 3-D

When enabled, sufficiently fast vertical mouse movement contributes forward or backward movement using a framerate-independent motion-rate threshold

Push-to-move remains independent from horizontal mouselook, mouse sensitivity, and Y-axis inversion. The option is disabled by default and persists through the normal settings save and load process

## Control Options Scrolling

The additional mouse option no longer requires the Control Options rows to be compressed

The menu now uses a fixed-spacing scrolling viewport with shared panel geometry, clamped scroll tracking, absolute item indices, correctly aligned cursor placement, and pixel-art overflow indicators

This preserves the established menu spacing while allowing every control option to remain reachable through keyboard, mouse, gamepad, and touch-capable input

## Classic Run-Speed Tuning

The player run-speed multiplier was increased from `1.6` to `1.75`

The change provides a stronger classic sprint response without altering normal walking speed or the established input paths used to activate running

## Classic 320 Rendering

Davenstein now provides a Classic 320-wide render-scale selection designed to reproduce the original game's coarse internal presentation on modern high-DPI displays

The internal canvas uses a fixed width of 320 pixels and derives its height from the active viewport aspect ratio so rendered pixels remain square

Additional lower relative render-scale steps provide intermediate choices between the previous percentage settings and the fixed Classic mode. Every new selection is represented by a stable persisted settings value

Changing the internal canvas size now deactivates its cameras for one frame while the color and depth targets are reallocated together. This prevents the depth attachment from retaining the previous dimensions and eliminates the resulting render-pass validation crash

## Fullscreen Resolution Safety

Exclusive-fullscreen resolution lists now contain only modes backed by real monitor-mode information and reported as settable by the active display

The resolution submenu cursor uses the same filtered index list as the visible rows, preventing the highlight from drifting after unsupported modes are removed

Requests for a mode that the display cannot set now fall back safely instead of allowing the windowing backend to panic, silently ignore the change, or leave the display in an unusable state

The filtering applies across supported desktop platforms whenever trustworthy monitor-mode data is available

Davenstein no longer offers exclusive fullscreen on macOS. Persisted or imported exclusive-fullscreen selections are converted to borderless fullscreen, which fills the native display without the disruptive display-capture and desktop-rearrangement behavior of exclusive mode

## Projectile Wall Collision

Projectile movement now checks the complete swept segment between its previous and proposed positions instead of testing only the final endpoint

The travel segment is clipped at the first wall before player and static-collision tests are evaluated. A fast projectile can therefore neither pass through a wall nor strike the player through intervening solid geometry

## Wolfenstein 3-D Door Toggling

Using an already-open door now requests that the door close, matching Wolfenstein 3-D's `OperateDoor` toggle behavior

The implementation expires the existing hold-open timer and lets the established automatic closing path perform the operation. Existing obstruction checks, clearance behavior, animation, and closing sound remain intact

## Current-Frame Weapon Input

Weapon firing and viewmodel processing now run after `InputGather`

The weapon system therefore reads the current frame's fire press consistently with the other gameplay input consumers. This removes an ordering-dependent condition where a single-frame press could occur before input gathering and intermittently drop the first shot

## Get Psyched Presentation

The Get Psyched loading screen now uses the final dark Wolfenstein 3-D play-screen teal

The loading overlay extends across the status bar's scaled top-border pixels, eliminating the visible separator while preserving the remainder of the HUD

The red progress bar is inset within the painted banner and positioned on the lowest black row immediately above the gray bottom frame

The status-bar image no longer contains the incorrect raised bevel on its extreme left edge. The image dimensions, panel coordinates, portrait, labels, dividers, and remaining HUD content remain unchanged

## Wolfenstein 3-D Quit Confirmation

Choosing Quit from either the main menu or the in-game pause menu now opens a modal confirmation box over the frozen frame

The prompt randomly selects from the nine original Wolfenstein 3-D quit taunts. The eighth message uses its original line wrapping and standalone `>` prompt marker

The input that selected the Quit menu row is absorbed so Enter or gamepad confirmation cannot immediately answer the newly opened prompt

An explicit Y key or gamepad confirmation exits the application. N, Escape, gamepad cancel, a mouse click, or another non-confirming input dismisses the prompt

Dismissal input is latched until it has been released, preventing the same Escape or gamepad action from also reaching the pause menu and immediately returning the player to gameplay

## Validation Scope

Local Davenstein 1.4.0 release-candidate validation completed successfully on macOS 26.6 using an Apple M5 Pro system with 64 GiB of memory

The Rust 1.97.1 release build completed successfully, `assets.pak` was rebuilt with 1,025 files, and the resulting release executable launched through the Metal renderer

Before tagging, final validation requires the complete Rust test suite, native debug and release builds, another asset-pack build, focused runtime regression checks, and a clean source-tree diff

Focused runtime validation should cover AdLib and PC Speaker selection and persistence, Retrolink and modern controller behavior, mouse push-to-move, Control Options scrolling, Classic 320 resizing, fullscreen transitions, projectile wall collision, open-door closing, first-shot input, Get Psyched presentation, and quit-confirmation input isolation

The tagged GitHub workflow validates the release version against `Cargo.toml`, builds the existing package matrix, performs its package-specific integrity and installation checks, and publishes this document as the GitHub release body only after all required jobs succeed

## Compatibility Notes

Davenstein 1.4.0 retains the public platform, architecture, package, and distribution matrix used by Davenstein 1.3.1

The Windows, Linux, macOS, FreeBSD, and Android release packages remain public. iPhone and iPad support remains limited to private physical-device development and approved local validation paths

The Retrolink mapping is limited to the verified `0079:0011` controller on macOS and does not replace mappings for modern analog gamepads

Mouse push-to-move is optional and disabled by default

macOS fullscreen operation now uses windowed or borderless fullscreen rather than exclusive display capture

PC Speaker mode falls back to the normal digitized sample when no corresponding beeper-tone mapping exists
