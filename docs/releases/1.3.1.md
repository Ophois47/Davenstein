# Davenstein 1.3.1

Davenstein 1.3.1 is a corrective maintenance release focused on gameplay accuracy, enemy line-of-sight behavior, mobile presentation, controller compatibility, high-score integrity, and Apple-platform runtime polish

The release restores authentic difficulty-based enemy damage, prevents actors from attacking or automatically noticing the player through obstructing geometry, finalizes the iOS startup-rendering correction, improves native mobile interface scaling and safe placement, adds complete support for stickless D-pad controllers, and hardens high-score entry and loading

Davenstein 1.3.1 does not add new public package formats or release targets. It refines the cross-platform architecture introduced in Davenstein 1.3.0 while retaining the existing Windows, Linux, macOS, FreeBSD, Android, private iPhone and iPad, and alternate-architecture support model

## Major Corrections

- Restored difficulty scaling at the live enemy hitscan and projectile damage paths
- Set the easiest skill to the authentic Wolfenstein 3-D quarter-damage behavior
- Prevented enemy shots from passing through corners by tracing between real world positions
- Required real line of sight for close-range automatic enemy notice
- Corrected native 320x200 mobile menus, scores, name entry, and end-of-level tally presentation
- Added minimum touch-edge clearance for rounded handheld displays
- Moved the mobile menu D-pad clear of landscape camera housings
- Replaced persistent touch labels with a once-per-session onboarding cue
- Added touch-specific high-score carousel guidance and removed obsolete keyboard prompts
- Eliminated the intermittent iOS magenta startup flash during Metal surface initialization
- Corrected intermittent macOS cursor reappearance during focused gameplay
- Added a complete D-pad-only control scheme for NES and SNES-style gamepads
- Added gamepad-only hitscan aim assistance without rotating the view
- Rejected blank and malformed high-score names and sanitized loaded entries

## Authentic Difficulty Damage Scaling

Enemy damage previously bypassed the selected skill level at the live attack sites, leaving every difficulty effectively capable of applying the same raw hitscan and projectile damage

Davenstein 1.3.1 applies `SkillLevel::damage_multiplier` where enemy hitscan and projectile damage are committed. The easiest skill now uses the original Wolfenstein 3-D quarter-damage behavior represented by `points >>= 2`, so "Can I play, Daddy?" no longer inflicts four times the intended damage

The correction changes damage received by the player without altering enemy health, movement, attack selection, or projectile trajectories

## Enemy Shooting Line Of Sight

Enemy shooting now traces between the actor's and player's real world positions instead of relying only on tile-center geometry

This prevents an actor from firing through a corner after the player has moved behind solid cover while preserving the existing coarse tile-based visibility test used to govern waking and broader awareness

## Close-Range Enemy Awareness

The close-range `MINSIGHT` auto-notice path now requires an unobstructed line of sight before an actor automatically senses the player

Walls and closed doors therefore block point-blank notice. This is a deliberate correctness divergence from the original Wolfenstein 3-D behavior, whose close-range shortcut did not perform the additional obstruction check

## Mobile Native Presentation

Short landscape mobile displays could remain at integer scale 1 even when a small tolerance would allow the native 320x200 interface to fit cleanly at scale 2

Davenstein 1.3.1 adds a narrow integer-scale snap tolerance for mobile menus, high-score entry, score screens, and the end-of-level tally. Desktop resolutions retain their previous scaling behavior

The mobile menu D-pad's left column is also inset to clear landscape camera housings without changing the broader touch-control geometry on tablets and desktops

## Touch Layout And Onboarding

The touch layout now enforces a 20-pixel minimum edge inset so corner-anchored controls clear rounded display corners even when the proportional margin would otherwise resolve to a smaller value

Persistent faint MOVE and LOOK labels have been replaced by larger soft-pill labels shown once on the first gameplay entry of each application session. A timed fade removes the onboarding cue after it has served its purpose

Tap-anywhere screens no longer display a redundant TAP TO CONTINUE label, and mobile game-over and name-entry screens no longer show desktop-only Enter-key instructions

## Touch High-Score Entry

Mobile high-score entry now displays an on-screen D-pad carousel legend describing the existing touch controls

The legend documents up and down letter selection, rightward cursor advancement, and explicit confirmation, replacing the hidden keyboard prompt with instructions that match the actual handheld input path

## iOS Startup Rendering

The earlier black-clearing camera prevented most pre-splash exposure but could not completely eliminate an intermittent magenta frame presented while the Metal surface was being configured

Davenstein 1.3.1 starts the primary mobile window hidden and reveals it only after cleared frames are available. The existing lowest-order background camera continues painting black behind subsequent splash and gameplay rendering

This prevents the uninitialized Metal drawable from being composited to the screen rather than attempting to cover it after presentation

## macOS Cursor Lock Recovery

macOS could silently release pointer lock and allow the cursor to reappear during gameplay without changing the cached application state

The focused gameplay path now reasserts the hidden and locked cursor state every frame, recovering from the operating-system release within a frame. Background focus loss still releases the cursor normally and does not repeatedly fight the operating system while Davenstein is inactive

## D-Pad-Only Controller Scheme

Stickless NES and SNES-style controllers now have a complete gameplay control scheme

The D-pad drives movement and fixed-rate turning, holding North enables strafing, the left shoulder enables running, West or East activates use, South or the right trigger fires, and the shoulder and Select controls cycle through currently owned weapons

Weapon selection uses a relative `weapon_step` intent and `HudState::cycle_weapon`, avoiding assumptions that a compact controller exposes a full numbered weapon row

## Gamepad Hitscan Aim Assistance

Gamepad-fired hitscan attacks now receive a small angular fallback when the exact ray misses an enemy hitbox

The fallback searches a configurable cone of approximately seven degrees and still requires valid line of sight and weapon range. It does not rotate the camera or modify player orientation

Mouse and keyboard shots continue using an aim-assistance angle of zero and retain exact hitbox aiming

## High-Score Entry Hardening

DJP now occupies the leading position in the default high-score table

Submitted names are stripped of control characters and surrounding whitespace, and empty or whitespace-only initials are rejected. Loaded high-score entries are sanitized through the same rules so malformed persisted data cannot produce a blank standings row

## Validation Scope

Before tagging, the Davenstein 1.3.1 release candidate requires the complete Rust test suite, native debug and release builds, focused gameplay regression checks, and the existing continuous-integration package and architecture gates

Focused runtime validation must cover difficulty-scaled enemy damage, corner-blocked enemy attacks, obstructed close-range notice, mobile native scaling, touch onboarding, high-score entry, D-pad-only gameplay, gamepad aim assistance, iOS startup rendering, and macOS cursor capture

The public package matrix and the private iPhone and iPad validation model remain unchanged from Davenstein 1.3.0

## Compatibility Notes

Davenstein 1.3.1 retains the public platform, architecture, package, and distribution matrix introduced in Davenstein 1.3.0

The Windows, Linux, macOS, FreeBSD, and Android release packages remain public. iPhone and iPad support remains limited to private physical-device development and unsigned device and simulator compile proofs

Gamepad aim assistance applies only when the shot originates from gamepad input. Mouse and keyboard aiming remain exact

The D-pad-only scheme is intended for compact controllers without usable analog sticks. Existing analog-stick and keyboard controls remain available

The specific Retrolink SNES controller remains unsupported in this release. An explicit SDL mapping was attempted, but physical testing did not produce working input, so Davenstein 1.3.1 does not claim compatibility with that controller

The close-range line-of-sight requirement deliberately differs from the original Wolfenstein 3-D `MINSIGHT` shortcut so solid walls and closed doors consistently block detection
